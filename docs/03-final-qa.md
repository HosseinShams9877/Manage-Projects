## جزئیات هر مرحله

### مرحله ۱ — بیلد، مهاجرت و سید از صفر `[OK]`

```bash
rm prisma/dev.db
npx prisma migrate deploy   # → 20261107122414_init applied
npx tsx prisma/seed.ts      # → ✅ سید با موفقیت اجرا شد (۶ کاربر، ۲ پروژه)
npx next start -p 3100
curl /login                 # → HTTP 200
```

### مرحله ۲ — دسترسی بدون احراز هویت و ورود ناموفق `[OK]`

- `GET /` (بدون کوکی) → `307 → /login` (هدایت میان‌افزار).
- `GET /api/dashboard/admin` (بدون کوکی) → `401 {"message":"دسترسی غیرمجاز است.","code":"UNAUTHORIZED"}`.
- `POST /api/auth/login` با رمز اشتباه → `401 {"message":"ایمیل یا رمز عبور نادرست است.","code":"INVALID_CREDENTIALS"}`.

### مرحله ۳ — ورود مدیر و رندر داشبورد مدیر `[OK]`

- `POST /api/auth/login` (مدیر) → `200` با `{"user":{"name":"مدیر سیستم","role":"ADMIN"}}` و کوکی جلسه.
- `GET /admin` → `200`؛ پوستهٔ SSR شامل عنوان «داشبورد / خلاصه وضعیت پروژه‌ها و پرداخت‌ها.»
  و اسکلتون‌های بارگذاری (`animate-pulse`) برای خروجی‌های `useAdminDashboard` است
  (داشبورد مدیر یک Component سمت-کلاینت است و داده را از `GET /api/dashboard/admin` می‌گیرد).

### مرحله ۴ — صحت اعداد داشبورد مدیر `[OK]`

`GET /api/dashboard/admin` (مدیر) → `200`. مقادیر با جمع‌ها از `dev.db` مطابقت دارند:

### مرحله ۵ — محافظت نقش‌ها روی APIهای داشبورد `[OK]`

- `GET /api/dashboard/admin` با کوکی **کارمند** → `403 FORBIDDEN` («شما اجازه انجام این عمل را ندارید.»).
- `GET /api/dashboard/me` با کوکی **مدیر** → `403 FORBIDDEN` (این مسیر فقط برای نقش EMPLOYEE است).

### مرحله ۶ — ورود کارمند و رندر `/me` `[OK]`

- `POST /api/auth/login` (ali) → `200` با `role: "EMPLOYEE"`.
- `GET /me` → `200`. HTML حاوی همهٔ بخش‌های Phase 5 به‌علاوهٔ موارد جدید Phase 6 است:
  «پروژه‌های من»، «اقساط پیش‌رو»، «دریافتی این ماه»، «اعلان‌ها»، «پرداخت‌های من».
- مبالغ به تومان و با ارقام فارسی و جداکنندهٔ «٬» رندر شده‌اند:
  `۷۰٬۰۰۰٬۰۰۰ تومان`، `۱۰٬۰۰۰٬۰۰۰ تومان`، `۶۰٬۰۰۰٬۰۰۰ تومان`، `۰ تومان` …
- هیچ تاریخ میلادی خامی (`YYYY-MM-DD`) در خروجی رندرشده وجود ندارد.

### مرحله ۸ — محافظت نقش‌ها روی صفحات `[OK]`

- `GET /admin` با کوکی کارمند → `307 → /me`.
- با کوکی مدیر: `/admin/projects`، `/admin/employees`، `/admin/employees/balances`،
  `/admin/notifications`، `/admin/projects/demo-project-1`، `/admin/employees/…` همه `200`.
- با کوکی علی: `/me/notifications`، `/me/payments`، `/me/projects` همه `200`.

### مرحله ۹ — اعلان‌ها `[OK]`

- `GET /api/notifications` (ali) → `200` با پیام‌های فارسی و مبالغ تومان فارسی
  (مثلاً «پرداخت ۳۵٬۰۰۰٬۰۰۰ تومان از پروژه «…» ثبت شد.»).
- `GET /api/notifications/unread-count` → `{"count":4}`.
- `POST /api/notifications/{id}/read` با بدنهٔ `{}` → `200` و شمارش خوانده‌نشده به `۳` کاهش یافت.
  (بدون بدنهٔ JSON → `400 INVALID_INPUT`، رفتار صحیح اعتبارسنجی.)
- **نکته:** نقطهٔ پایانی به یک بدنهٔ JSON (حتی `{}`) نیاز دارد؛ این رفتار Phase 5 است و تغییر نکرده است.

### مرحله ۱۰ — ممیزی تاریخ شمسی، ارقام فارسی و زمان نسبی `[OK]` — ۱ باگ اصلاح شد

| زنجیره (route) | مسیر (path) | فایل |
| :--- | :--- | --- |
| GET | `/api/me` | `src/app/api/me/route.ts` |
| GET | `/api/notifications` | `src/app/api/notifications/route.ts` |
| GET | `/api/notifications/unread-count` | `src/app/api/notifications/unread-count/route.ts` |

- تاریخ‌ها همه به شمسی (`۱۴۰۵/۰۱/۰۱`) و ارقام به فارسی هستند؛ خروجی‌های زمان نسبی
  همگی صحیح هستند: `۸ ماه پیش`، `یک سال پیش`، `۲ ماه پیش`.

> **باگ یافت‌شده و اصلاح‌شده:** تابع `formatJalaliRelative` برای محاسبهٔ «پیش/در»
> از `d.fromNow()` استفاده می‌کرد که یک نمونهٔ jalali را با یک `dayjs()` گریگورین
> مقایسه می‌کرد. افزونهٔ relativeTime اختلاف ماه/سال را با قلاب‌های تقویم هر دو طرف
> محاسبه می‌کند، در نتیجه خروجی‌ها بی‌معنی بود (برای ۸ ماه پیش: «۱۲ سال پیش»،
> برای ۱۱ ماه پیش: «در ۸ سال»). اصلاح: هر دو طرف با `.locale("fa").calendar("jalali")`
> پیچیده می‌شوند و سپس `d.from(nowJalali)` محاسبه می‌شود
> (`src/modules/notifications/lib/relative-time.ts`). پس از اصلاح، همهٔ ۸ رویداد
> داشبورد و اعلان‌ها زمان نسبی صحیح نمایش می‌دهند. این تنها تغییر رفتار Phase 6
> است؛ سایر رفتارهای Phase 1–5 دست‌نخورده باقی ماند.

### مرحله ۱۱ — صفحهٔ ۴۰۴، خروج و پاک‌شدن جلسه `[OK]`

- `GET /some-missing-page` با کوکی مدیر → `404` با متن فارسی
  «صفحه‌ای که دنبالش بودید پیدا نشد» و دکمهٔ «بازگشت به داشبورد».
  (بدون احراز هویت میان‌افزار ابتدا به `/login` هدایت می‌کند → رفتار صحیح.)
- `POST /api/auth/logout` → `200` و کوکی با `Max-Age=0` پاک می‌شود.
- `GET /me` پس از **به‌روزرسانی کلاس کوکی** → `307 → /login`.
  > **طراحی Phase 1 (بدون تغییر):** جلسه یک JWT بدون‌حالت (stateless) است؛ خروج
  > فقط کوکی کلاینت را پاک می‌کند و توکن قبلی را باطل نمی‌کند.

## محدودیتهای شناخته‌شده (بدون تغییر)

۱. `/api/dashboard/me` فقط برای `EMPLOYEE` قابل دسترس است؛ مدیر که بخواهد داشبورد
   یک کارمند را بباید از مسیرهای Phase 5 (`/admin/employees/[id]`) استفاده کند.
۲. `/admin/notifications` و `/me/notifications` داده‌ها را سمت-کلاینت (React Query)
   می‌گیرند، بنابراین HTMLِ SSR ابتدا «در حال بارگذاری…» نشان می‌دهد.
۳. خروج یک JWT بدون‌حالت (stateless) است (مرحله ۱۱).
